# Enterprise Readiness Checklist

## Purpose
Track the detailed steps required for this NL-to-SQL agent to match enterprise standards.

Legend:
- `[x]` implemented or mostly implemented
- `[~]` partially implemented / needs hardening
- `[ ]` not implemented yet

## 1. Input Processing
- [x] Normalize user input before retrieval.
  - Current: `TextNormalizer` uses Lucene analysis.
- [x] Correct typos before retrieval.
  - Current: `VocabularyCorrectionService`.
- [x] Use maintained vocabulary instead of hardcoded correction terms.
  - Current: in-memory vocabulary and PostgreSQL `retrieval_vocabulary`.
- [x] Support typo types like transposition.
  - Current: edit-distance/transposition rerank.
- [~] Add production metrics for correction quality.
  - Needed: log correction candidate count, chosen correction, score, ambiguity, and source type.

## 2. Schema And Retrieval Indexing
- [x] Extract schema metadata dynamically.
  - Current: JDBC metadata extraction.
- [x] Build schema chunks dynamically.
  - Current: table, column, primary key, foreign key metadata.
- [x] Build join-path chunks from foreign keys.
  - Current: generated by `SchemaChunkBuilder`.
- [x] Detect schema drift with schema fingerprint.
  - Current: fingerprint changes when tables, columns, keys, or FKs change.
- [x] Rebuild vocabulary and embeddings when schema index changes.
  - Current: `SchemaIndexService` support-index rebuild.
- [~] Support multiple metadata providers.
  - Current: provider interface exists.
  - Needed: provider-specific PostgreSQL, MySQL, Oracle, SQL Server implementations and tests.

## 3. Business Rules
- [x] Remove hardcoded Java business rules from production retrieval path.
  - Current: rules loaded from external YAML.
- [x] Validate business-rule schema refs against active schema.
  - Current: stale refs excluded during chunk building.
- [~] Move rules to governed storage.
  - Current: YAML bootstrap.
  - Needed: DB tables with owner, version, approval status, effective dates, datasource, tenant, aliases, schema refs.
- [ ] Add rule approval workflow.
  - Needed: admin/API workflow and audit trail.
- [ ] Add contradiction detection between selected business rules.
  - Needed: rule conflict model and validator.

## 4. Vocabulary And Typo Search

  - Current: `retrieval_vocabulary`.
- [x] pg_trgm typo/fuzzy lookup.
  - Current: `PostgresTrigramVocabularyService`.
- [x] Edit-distance rerank after pg_trgm candidates.
- [~] Add PostgreSQL integration tests.

## 6. Retrieval Flow
- [x] Prepare schema, vocabulary, and embeddings before correcting input.
- [x] Correct user input before retrieval.
- [x] Retrieve typed chunks.
  - Current: schema, business rule, join path.
- [x] Use confidence threshold before SQL generation.
- [x] Retry retrieval with normalized, expanded, hybrid, and fallback modes.
- [~] Add explicit typed prompt-context object.
  - Current: internal chunks are typed, but `RetrievalContext` still exposes snippets.
  - Needed: `TypedPromptContext` with schema, rules, aliases, join paths, policy, dialect, confidence, chunk ids.
- [ ] Add typed prompt-context validator.
  - Needed: validate selected context before prompt construction.

## 13. Admin Management
Admin pages are needed for parts that are governed, reviewed, refreshed, or operated by humans.

- [ ] Business rules admin.
  - Manage rule text, aliases, schema refs, owner, approval status, version, effective dates, tenant, and datasource.
  - Highest priority because business rules should not stay in YAML long term.
- [ ] Schema index admin.
  - View active datasource schema snapshot, schema fingerprint, tables, columns, foreign keys, last refresh time.
  - Trigger refresh/rebuild.
- [ ] Retrieval diagnostics admin.
  - View user question, normalized query, corrected query, correction candidates, retrieved chunks, scores, confidence, failure codes.
  - Needed to debug bad or rejected answers.
- [ ] Vocabulary admin.
  - View generated terms, source type, source id, active status.
  - Test typo correction, for example `cutsomer -> customer`.
  - Trigger vocabulary rebuild.
- [ ] Embedding/vector admin.
  - View embedded chunks, embedding model, dimensions, content hash, last indexed time, active status.
  - Trigger re-embedding.
- [ ] Guardrail policy admin.
  - Manage allowed schemas/tables, denied tables/columns, max row limit, dialect rules, and future query-cost thresholds.
- [ ] Audit log admin.
  - View question, generated SQL, retrieved chunk ids, rule ids, guardrail decision, execution outcome, trace id, latency.
- [ ] Prompt/generation config admin.
  - Manage prompt version, dialect rules, generation model, repair retries, timeout, and max limits.
- [ ] MAG memory admin.
  - Later: manage sessions, result references, memory retention, TTL, redaction, and memory search/debug.

Recommended priority:

```text
1. Business Rules
2. Schema Index / Refresh
3. Retrieval Diagnostics
4. Vocabulary
5. Embeddings
6. Guardrail Policies
7. Audit Logs
8. Prompt Config
9. MAG Memory
```

First practical admin page:

```text
Business Rules + Rebuild Index
```
